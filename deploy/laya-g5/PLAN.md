# Laya 东京部署与同题对比计划

日期：2026-10-15。用户要求：研究 Laya，在东京区 g5.xlarge 部署并做一次对比，加入当前 report。

后续用户确认：g5.xlarge 两个可用区按需及 Spot 均缺容量后，改用东京 **g5.2xlarge**（仍为单张 A10G）。
按实际 g5.2xlarge 单价计算成本，并在报告中注明实例 CPU、内存不同。

## 固定方案

- 阅读上游源码、模型配置和许可，固定代码提交及 Hugging Face 权重 revision。
- 东京 `ap-northeast-1` 当前没有 running/stopped 实例；新建一台 g5.xlarge（A10G）。
  使用专用安全组，SSH 仅允许管理机出口地址；推理服务绑定 loopback，通过 SSH 隧道访问。
- 本批含中文，固定 `convaiinnovations/laya-multilingual`，不按答案选择检查点、不微调。
  设 `max_len=8192`，审计每题实际序列和截断情况；保留默认评分与概率解码。
- 复用报告的 76 个请求、147 个判断及原有标准答案。合并已存在的 UI 输入修正，
  不把 grade/expected 发给模型。只跑一次正式串行测试，不重试；冒烟和预热单独保存。
- 在东京 GPU 主机本地调用 loopback 服务计时，避免把美西至东京的网络时延算成推理性能。
  报告区分东京本机 HTTP 时延与其他模型原有的客户端时延，不能视为严格同网络条件。
- 使用既有 Jev schema 校验和 grade 函数。对比 147 题全量及去掉网格误用对照的 117 题。
  保存原始响应、逐题结果、复核状态、时间、运行环境、请求指纹、完整错误。
- 查询东京 g5.xlarge 的 Linux 按需价。推理批次机时折算与常驻实例开销分别说明，
  不将批次摊销当成完整账单。

## 验收

1. EC2 确认东京区、g5.xlarge、NVIDIA A10G，模型在 CUDA 上加载，健康与冒烟通过。
2. 正式记录 76 个请求且无遗漏；协议/运行失败原样报告，不事后改标准答案。
3. 修改报告生成器并重建 HTML；总览及成本页纳入 Laya，补充研究结论、局限与复现方法。
4. 离线复算所有新指标，运行相关检查，浏览器检查报告排版。
