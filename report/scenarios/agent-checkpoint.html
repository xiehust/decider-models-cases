🧭 Agent 执行检查点

Agent 最容易在三个时刻出错：命令反复失败、计划偏离需求、准备向用户报告完成。本场景在这三处各请 Jev 核对一次。

9/9 通过 · 复核 0判断数 9 模型 typesafe/jev-1.13-20260917运行日期 2026-10-12
场景介绍

业务背景

编码 Agent 执行长任务时，有几种失误很常见：一条命令失败后原样重试，计划越做越偏离用户的要求，或者把刚触发、还在排队的任务当成已完成告诉用户。出这些错的时候，Agent 手里的信息其实够用，只是在该停下来核对的地方没有核对。

本场景设了三个检查点，每个检查点交给 Jev 一份完整的状态，包括目标、用户规则、命令输出和候选动作。要它回答的只有几类问题：下一步选哪个，某个说法是否成立，完成的证据有多强。真正动手执行的仍是调用方。

为什么用 Jev

判断点

检查点上的判断次数多、选项少，主要是拿证据逐条对照，用不着长篇推理。交给类型化判断模型来做，比让主模型再想一遍便宜得多。

埋设的陷阱

  • 恢复：同一个 ModuleNotFoundError 已经出现三次，候选里混着一条违反用户规则的捷径，把包装进系统 Python。
  • 偏航：用户要求改动尽量小，计划却中途转去重写日志框架、升级 pandas。
  • 完成：流水线还在 running，健康检查返回的仍是旧版本 2.3.0，Agent 却已经报告部署成功。
触发方式

这个场景怎样触发 jev

Agent 启动时只读入每个技能的名称和 description，任务和 description 对得上，才加载完整的 SKILL.md 按其中的流程执行。本次测试跳过了自动匹配这一步，由验证脚本直接按技能流程构造请求。

技能的 description

Use TypeSafe Jev through OpenRouter or its official API for context-rich typed judgments rather than generated prose, especially high-volume classification, scoring and routing with parallel independent decisions. Define questions, choices or rubrics for ambiguous agent checkpoints (goal drift, repeated failures, tool routing, completion claims), browser states or human review. Supply sufficient relevant context in every request and batch independent questions. Use code for exact rules or arithmetic; Jev is advisory, not an authorization or security boundary.

通过 OpenRouter 或官方 API 调用 Jev，做依据充分的类型化判断而不是生成文字，尤其适合大批量、可并行的分类、打分和路由。可用于 Agent 拿不准的检查点（目标偏移、反复失败、工具路由、完成声明）、浏览器状态和人工复核。

本场景的触发时机

SKILL.md 的“何时使用”一节列了 Agent 模式下的几种时刻，本场景取了其中三种：同一条命令反复失败，需要换一条恢复路径；计划偏离了用户目标；排队中的任务被当成已经完成。到了这些时刻，Agent 停下来，把目标、用户规则、命令输出和候选动作整理成一份状态交给 Jev。

本次怎么调用

验证脚本扮演调用方，按 SKILL.md 的流程写好 3 个请求，经 jev-decide decide - --provider openrouter 各真实调用一次。

什么时候不该触发

指令清楚、精确匹配、算术、日期比较，或者需要写原创文字时，不用 Jev。SKILL.md 还提醒只在检查点调用，不要每个小动作之前都问一次。

核心结论

三个检查点都判断对了：它认出了违反用户规则的捷径，指出了计划偏航，也否定了“部署成功”的说法，要求等流水线跑完再核验。证据齐全、选项有限的检查点适合交给 Jev，但拦下违规动作仍要靠调用方的权限系统。

生产使用建议

  • 检查点不必每一步都设。命令失败两次以上、准备向用户报告完成、计划步数明显超出预期，这几个时刻值得问一次。
  • 判断是否完成时，noul（说法是否成立）和 score（证据强度）一起问，两个答案可以互相印证。
  • 用户规则要逐条写进 state。Jev 能认出违规的候选，但真正拦下它的应当是调用方的权限系统。
