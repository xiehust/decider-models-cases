场景介绍

业务背景

新成员常问“支付回调的签名在哪校验”“重试间隔在哪算”。关键字搜索容易被同名符号干扰：本仓库里 hmac 同时出现在支付回调和密码重置两个文件中，RETRY_MAX 常量在 config.py，而退避计算在 retry.py。

“密码重置邮件正文”这个功能并不存在：templates.py 只定义了发货和收款两个模板。

为什么用 Jev

判断点

候选是宿主真实读到的文件和源码，Jev 只在这些候选中选择。宿主随后打开文件、核对符号，选错可以回退，不会出现虚构的路径。

埋设的陷阱

  • hmac.compare_digest 同时出现在 passwords.py 和 webhooks.py。
  • “重试”相关的内容分散在 config.py（次数）和 retry.py（退避计算）两处。
  • templates.py 名字像“邮件模板”，但里面没有密码重置模板。

结论与建议

如何在生产中使用

  • 大仓库应先用代码图谱或索引缩小范围，再让 Jev 在已读过的候选中做语义选择。
  • 选中文件后，一定要用确定性工具核对符号确实存在。
