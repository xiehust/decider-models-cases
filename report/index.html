Decider 决策模型评测报告

Agent 要做选择、判是非、给评分时，到底该调用大模型，还是专门的决策模型？这份报告用 10 个贴近真实业务的合成应用场景、76 个共用请求、147 个判断，把 Jev、Strands Decider 2B、Laya Multilingual 三款决策模型，与 Claude Opus 5.5、Claude Haiku 5.5、GPT-6 Luna 放在相同的状态、问题和候选项下对比，覆盖准确率、复核行为、时延与成本四个维度。所有结论都附逐题输出和测量条件，并按具体场景给出“是否可用、用哪款”的选型建议。

基础

Decider 模型的三种输出

choice

从候选中选一个

输出候选标签及其概率，可用于类别、下一步动作、文件或条款 ID。需要设置 none、unknown 或 ask_user 等回退选项。

noul

判断是否成立

输出 P(true)，用于主张、约束或同一性判断。读取“否”的置信程度时，需要同时考虑 1-p。

score

按等级评分

返回各等级概率及加权分数，可用于严重度、紧急度和证据强度。分数可以是小数，按预定区间验收。

集成方式

决策模型与调用方的分工

这是建议的集成流程。模型负责判断，权限、执行与结果核验由调用方承担。本报告保留回执中的复核规则：choice 最高概率至少 0.8、相对次高至少高 0.15，出口标签转复核；noul 按二元确定程度处理。规则合适与否仍需用自己的数据验证。

方法

测试设计、证据范围与局限

  • 比较使用同一批 state / questions、候选及预定标准答案。标准答案不进入模型输入，未按结果修改评分区间。
  • 用例最初按 jev-skill v0.2.0 构建，后作为共享测试集；原始标识与回执保留。运行器的技能描述不是三种模型都具有对应能力的证明。
  • NPC、网格和 UI 的真实闭环由 Jev 驱动采集，其他模型重放相同状态判断。只有 Jev 有该闭环的执行与 DOM 证据；其他模型的逐步正确率不等于任务完成率。
  • 主要选型口径为 117 题，完整口径为 147 题。网格变体 B 和排除误用对照的统计口径是在看到变体 A 失败后追加的，属于事后分析。
  • LLM 单价沿用给定假设；自托管按实际地区和机型的按需机时折算，不含部署、空闲、EBS 等费用。Laya 使用东京本机 HTTP，其余记录的网络条件不同。
  • 每个输入 / 配置只测一轮，样本量小、用例来自同一作者。没有测试不同随机种子、所有检查点或微调后的能力；高置信度与场景排名都只能解释为本批证据。
