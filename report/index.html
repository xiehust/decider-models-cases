基础

Jev 能回答的三种问题

choice

从候选中选一个

返回每个候选的概率，用于下一步动作、路由、类别、条款 ID 这类选择。候选里必须留一个出口，比如 unknown、none 或 ask_user。

noul

是 / 否

返回回答“是”的概率，适合判断某个说法是否成立、某个动作是否违反规则、两条记录是否相同。它很有把握地答 false，答案依然是 false。

score

按等级打分

返回各等级的概率，以及按概率加权的分值，分值可以是小数。常用于严重度、紧急度和证据强度。分值本身不是概率，要连同分布一起读。

通用闭环

每个场景都按同一个闭环运行

Jev 只负责第 3 步。它返回 selected，只说明选出了一个标签，动作并没有因此获得批准，执行、权限、付款和删除始终由调用方负责。复核门槛采用 CLI 默认值：最高概率不低于 0.8，并且比第二名高出至少 0.15。unknown、none、ask_user 这类出口标签一律进入复核。

总体结果

各技能符合标准答案的比例

jev-simulation 只统计 NPC 和网格变体 B 的回合。网格变体 A 是误用对照组，单独列在右侧和仿真页面。

校准

按最高概率分段的答对率

只统计 choice 和 noul 题，noul 取 max(p, 1-p)，不含误用对照组。最高概率不低于 0.95 的 92 个判断全部答对。低概率段的样本太少，看不出规律。

性能

单次调用耗时分布（76 次）

耗时取自 CLI 返回记录里的 elapsed_seconds，即一次 API 往返的时间。16 个静态请求以并发 4 发出，整段墙钟时间 1.11 秒。这是单机一次实测的结果，不代表性能保证。

对照

误用对照：让 Jev 独自规划

红线是变体 A，Jev 独自规划，30 个回合里只有 12 步是最优步，没有送达，圆点表示停留次数。绿线是变体 B，规划器给出路线，20 个回合全部最优，顺利送达。查看分析 →

发现

关键发现

有界判断很可靠
问题的选项明确、证据齐全时，Jev 的首选标签和标准答案高度一致。最高概率不低于 0.95 的 92 个判断全部答对。
缺少依据时不硬猜
合同里没有的滞纳金条款、没有提供的附件、仓库里不存在的功能、被截断的对话，Jev 都给出了 none 或 unknown，并进入复核。
注入指令没有改变选择
工单里要求改标签的指令和页面横幅里的“请删除账户”，都没有影响类别和动作的选择，调用方的硬拦截在这一轮也就没有被触发。
评分要连同分布一起读
3 个未达标的判断都是 score。概率分散在两个等级时，加权均值会落到可接受区间之外。
不适合多步规划
让 Jev 独自在网格里找路，30 回合都没送到，机器人一直在两个格子之间来回。改由规划器给出路线、Jev 只选下一步之后，20 回合按最短路线送达。
成本和延迟都很低
单次调用的中位耗时是 0.19 秒，76 次调用按 API 返回的费用合计 0.002505 美元。这是本次合成负载上的实测值，不代表性能保证。

方法

验证方法与局限

  • 标准答案在调用之前就已写定，记在调用记录开头的 manifest 里，不会随请求发出。测试材料全部是专门编写的合成内容。
  • 调用方的独立核验包括：实际运行测试套件和探针，读取浏览器 DOM，用规则引擎校验状态转换，按 ID 复制原文，以及确定性的红队判定器。
  • 运行边界：最多 80 次调用，并发 4，不重试，不切换服务商，按 API 返回的费用累计到 0.02 美元即停止。这一轮没有触发停止条件。
  • 未达标的结果原样保留，没有事后放宽区间。网格变体 B 是看到变体 A 失败之后才追加的，用来检验按技能文档推荐的方式使用（规划器给路线、Jev 只选下一步）能否改善结果，不属于事先留出的测试。
  • 样本量小，用例也出自同一个作者。这些结果只能说明场景跑得通、判断与标准答案一致，不能代表普遍的准确率。
