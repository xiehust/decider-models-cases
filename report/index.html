Jev 应用场景验证报告

两个准确率口径是什么意思。 全部 147 个判断 = 16 个静态场景请求的 86 个判断 + 闭环场景的 60 个回合判断（NPC、网格变体 A、网格变体 B、浏览器 UI）。 其中网格变体 A的 30 个回合是刻意设计的误用对照组：Jev 技能文档要求路线由规划器给出、Jev 只选下一步， 而变体 A 只给地图、让 Jev 独自规划路线。“不含网格误用对照组的 117 个判断”就是把这 30 个回合去掉之后的口径， 所有方案都去掉同样的题；网格变体 B（规划器给路线）仍保留在内。
各方案在这 30 个对照组回合上答对：Jev 12/30；Strands Decider 2B（自托管） 6/30；GPT-6 Luna · 只答案 30/30；GPT-6 Luna · 答案+理由 29/30；Claude Haiku 5.5 · 只答案 30/30；Claude Haiku 5.5 · 答案+理由 30/30；Claude Opus 5.5 · 只答案 30/30；Claude Opus 5.5 · 答案+理由 30/30。答对最少的是 Strands Decider 2B（自托管）；Jev 答对 12 个， 这是它在两个口径下准确率差别较大（85.7% 与 97.4%）的原因。
说明：变体 A 本身是事先设计的对照组，但“单列 117 题口径”是在看到 Jev 在变体 A 上失败之后才增加的统计方式，不属于事先确定的评测方案。 右侧副坐标是把同一个答对数换算成占该口径总题数的百分比。
最便宜：Jev $0.0025；最便宜的 LLM 是 GPT-6 Luna · 只答案（$0.0079）， 是 Jev 的 3.1 倍；自托管 Decider 按机时为 $0.0030（1.2 倍）。

最准（不含网格误用对照组）：Claude Haiku 5.5 · 只答案 116/117（99.1%）； Jev 114/117（97.4%）。全部 147 题时 Jev 为 126/147（85.7%），差距主要来自让它独自规划的误用对照组。不含网格误用对照组时，Strands Decider 2B（自托管）、GPT-6 Luna · 答案+理由、GPT-6 Luna · 只答案 的准确率低于 Jev，费用却更高。

基础

Jev 能回答的三种问题

choice

从候选中选一个

返回每个候选的概率。适合下一步动作、路由、类别、条款 ID。必须提供 unknown / none / ask_user 这类兜底选项。

noul

是 / 否

返回“是”的概率。适合“主张是否成立”“是否违反规则”“两条记录是否相同”。一个很有把握的 false 仍然是 false。

score

按等级打分

返回各等级的概率和加权分值（可以是小数）。适合严重度、紧急度、证据强度。分值不是概率，需要配合分布阅读。

通用闭环

本报告中每个场景都遵循的决策闭环

Jev 只负责第 3 步。返回 selected 只代表“选出了一个标签”，不代表动作获得了批准； 执行、权限、付款和删除等操作始终由宿主负责。复核门槛采用 CLI 默认值：最高概率 ≥ 0.8，且领先第二名 ≥ 0.15； unknown / none / ask_user 等兜底标签总是进入复核。

总体结果

各技能通过预设的比例

jev-simulation 只统计 NPC 和网格变体 B 的回合；网格变体 A 作为误用对照组单独列出，见右侧和仿真页面。

校准

最高概率分段与预设一致率

只统计 choice 和 noul（noul 取 max(p, 1-p)），不含误用对照组。 概率 ≥ 0.95 的 92 个判断全部与预设一致。低概率段样本很少，不足以下结论。

性能

单次调用耗时分布（76 次）

耗时取自 CLI 回执中的 elapsed_seconds（API 往返）。16 个静态请求并发 4 发出，整段墙钟时间 1.11 秒。这是单机单次实测，不代表性能保证。

发现

关键发现

有界判断很可靠
在答案空间明确、证据齐全的问题上，Jev 的首选标签与预设高度一致；顶部概率不低于 0.95 的 92 个判断全部与预设一致。
“不硬猜”机制有效
缺失滞纳金条款、未提供的附件、不存在的代码功能、截断的对话，都正确落到 none / unknown，并进入复核。
能抵抗注入的选择
工单中的改标签指令、页面横幅的“请删除账户”都没有改变类别和动作选择；宿主的硬拦截在本轮没有被触发。
评分的加权均值需要配合分布阅读
3 个未达标判断都是 score：概率质量分散在两个等级时，加权均值会落在预设区间之外。
不适合多步规划
让 Jev 独自在网格中寻路，30 回合未送达，在两格之间来回摆动；改由规划器给出路线、Jev 只做局部选择后，20 回合按最优路线送达。
成本与延迟很低
单次调用中位耗时 0.19 秒，76 次调用的 API 回报费用合计 0.002505 美元；这只是本次合成负载的实测，不代表性能保证。

方法

验证方法与局限

  • 所有预设答案在调用前固定，并写入回执的 manifest；预设答案不进入请求。所有材料都是专门编写的合成内容。
  • 宿主侧独立核验：真实运行测试套件和探针、读取浏览器 DOM、规则引擎校验状态转换、按 ID 复制原文、确定性的红队判定器。
  • 运行边界：最多 80 次调用、并发 4、无重试、不切换服务商；累计回报费用达到 0.02 美元即停止。实际没有触发停止条件。
  • 未达标项原样保留，没有事后放宽区间。网格变体 B 是在看到变体 A 失败之后追加的，它验证的是“按技能文档推荐方式使用（规划器给路线、Jev 只选下一步）”的改进，不属于事先留出的测试。
  • 样本量小、用例由同一作者编写，结果只说明这些场景可以运行、判断符合预设，不能代表普遍准确率。
